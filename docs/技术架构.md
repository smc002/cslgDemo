初始英雄新增 `shield`、`medic`、`drone` 序列帧；`shared/hero-animation.ts` 统一注册五名已有动画英雄，剪辑支持 `sheetWidth/sheetHeight/impactFrame`。新角色动作使用 384px 单元和固定 (192,364) 地面锚点，角色按 pixelsPerUnit 显示到原战斗大小。肖像读取真实图集尺寸，避免旧代码固定 1774×887。

`scripts/build-starter-animations.mjs` 将三张生成原图按透明连通轮廓分帧，处理医疗兵/无人机手相邻行细小连接与跨格无人机，剔除外沿极低 alpha 杂点对包围盒的影响；行走归一高度与头部横向锚点，攻击/死亡保留统一尺度。输出待机、移动、普攻、技能、死亡图集和裁切记录。原图保留在 `public/assets/animations/starter-source`。

`merged/simulation.ts` 的初始三英雄采用 animation 状态，命中帧再执行原伤害/治疗/发射；死亡取消待命中动作。医疗子弹起点按当前帧枪口计算，无人机子弹按环绕位置计算。`scripts/test-animation.mjs` 已覆盖 0、1、2、3、8 五位英雄。

猎场清单使用 `zombies-isolated.png` 和 `zombiePadding:47`，`hunt/view.ts` 的 `zombieSprite` 统一处理主体/死亡残影的 512px 单元与边距坐标补偿。`scripts/fix-hunt-zombie-crops.mjs` 可复现切图，`scripts/check-hunt-zombie-crops.mjs` 可做独立实际 Canvas 验收。

内城使用 `city/CityPanel.tsx` + `city/city-scene.css` 叠加独立建筑到整屏地面。建筑是带语义和键盘支持的透明图片按钮，以轮廓 drop-shadow 和地面椭圆表现高亮。选择后显示非模态底部操作面板，地图上移让出空间。素材 `public/assets/city-scene` 包含地面、两套六阶段图集、统一 512×512/底部锚点 (256,500) 的十二张切图、提示词和裁切元数据。

建筑阶段阈值为 `[0,1,2,3,5,8]`，真实等级最大 10，图片状态直接从持久化等级推导，不额外写美术状态。所有建造/产出动作继续调用原 `buildCity` / `collectCity` / `production`，没有改变经济规则。`scripts/slice-city-scene.ps1` 可重现切图。

`bright-ui.css` 在 phone-ui 布局之后应用 A 版图片皮肤。UI 图集中所有底板无字，运行数据仍为 DOM 文本/进度；导航图标来自原始选中概念。拆图脚本 `scripts/slice-bright-ui.ps1` 保留裁切坐标与透明处理，源图和提示词均在项目内。

猎场输入：`press` 记录一次待发射击，`release(true)` 允许快速轻点在下一模拟帧完成一次射击；通常 `release()` 清除请求。冷却独立于按下/松开，频繁点击不能绕过 4 发/秒。自动连射只由明确的开火按钮开启，鼠标悬停不改变瞄准。

## 模块

- `components/gameplay-menu.tsx`：四模块路由、共享等级资源栏、实时搜刮小窗、目标面板、设置和重置。`phone-ui.css` 统一限定手机竖屏视口；猎场推图窗位于左下角，其它页面为较矮的状态提示，所有顶部/底部栏位均在同一视口内。弹窗同样限定到手机视口宽度。
- `merged`：固定 60Hz 三路战斗及 Canvas 绘制。campaignMode 使用明确关卡，3 波结束进入 cleared；UI 提交首通并决定自动下一关/首领布阵。组件保持挂载，切换页面只改变尺寸，不暂停模拟。
- `hunt`：从 E:/mori/demo 恢复的猎场模拟、画布与新 UI。离开猎场会保存弹道/僵尸/奖励状态并销毁该视图，重新进入从存档恢复；搜刮同时继续。
- `recruit`：九英雄招募、收藏、升星与品质进阶。完整成品英雄池不再包括旧版其余十一张仅展示卡面。
- `city`：两种生产建筑、建造升级、时间戳累计及手动领取。
- `lib/campaign.ts`：v2 主存档、首通、培养、生产、限次补给和单标签页操作租约。
- `lib/recruit.ts`：heroId/战斗索引/品质/卡面映射与抽取。
- `lib/hunt-save.ts`：恢复旧猎场存档类型、校验及累计耗弹英雄奖励提交；仅作为纯数据适配，旧存档 singleton 未带入。
- `lib/hunt-economy.ts`：原隐藏奖池、实际耗弹账本、派生奖励预算与运行时快照。
- `lib/balance.ts`：首轮经济、关卡与时间参数。具体英雄参数在 merged/simulation；旧猎场收益细则在 hunt-economy。
- `shared`：动画适配、九英雄头像、公共样式与切图。动画元数据放 shared/animation-data，避免开发服务器禁止直接导入 public 中 JSON 的问题。公开资源另保留原 JSON 供资产查看。

## 状态与结算

浏览器来源内使用 `mori.demo.campaign.v2`。旧版 `mori.demo.campaign.v1` 不删除，初次进入新版本额外备份为 `.backup`；因为旧版波次发券经济不兼容，本版新开三人初始进度，不隐式兑换旧资产。租约 `mori.demo.lease.v2` 控制单个活跃实例。

主存档保存 bestStage、黑金弹、核心/共享等级、累计发券与已耗券、拥有数量、品质星级及已消耗重复份数、九格阵容、建筑与时间戳、应急次数和冷却。统一 heroId 贯穿战斗与养成。核心累计和当级经验分别保存。关卡只允许顺序首通，已完成关卡不重复发奖励。

猎场扣弹先在同步回调中记 pendingDebit，紧接着连同弹道收据/奖池/核心存档原子提交。核心越过新的 200 分里程碑才增加累计券。运钞奖励以 completed serial 去重，击破和英雄入库在演出之前一起提交。UI 提示后显示，不用动画完成回调发放道具。

内城使用领取时间戳计算批次数，最多 20 批；领取后保留当前周期余量，重复点击不会再次领取。升级按旧等级结算，然后重置生产周期。时钟向后调整不会发负产物；本地存档非防作弊系统，不承诺抵抗用户修改设备时间或存储。

战斗过程中培养成长按比例修改最大生命/当前生命并更新伤害治疗系数，不复活死亡单位。阵容只在准备阶段修改。每关开始重新部署；刷新从未完成关卡第一波恢复，不保存精确战斗瞬间。挂起浏览器不补算离线战斗时间。

## 动画和资源

大刀/狙击两套 PNG/JSON 从 Unity 验证资产复制，运行不访问 Unity 目录；初始三英雄在 v0.6 新增生图与序列帧。裁切矩形、脚底 anchor、pixelsPerUnit 保持角色稳定。大刀 slash/每三次 slam，狙击 crouch；初始三人 attack/skill；命中关键帧只结算一次，死亡取消未触发攻击并保持死亡终帧。仍为单一斜背方向+镜像；其余四位角色尚未扩充序列帧。

本轮 imagegen 原图复制到 public/assets/loop，猎场旧资产复制到 public/assets/hunt。没有调用远程资源服务、账号或数据库。构建产物不依赖 E:/mori 和 Unity 源工程。

## 验证和限制

`test-merged` 覆盖同路攻击治疗、刺客、技能和模拟生命周期；`test-animation` 覆盖关键帧伤害及暂停/死亡；`test-loop` 覆盖真实三波清关、一次性奖励、扣弹与核心、招募上阵、内城产出和封顶、品质进阶与存档往返、应急限制与橙卡去重。`test-hunt-cadence` 验证连续瞄准更新不会重置射击冷却，5 秒 20 发、松手停止及暂停恢复。

猎场绘制统一用水平比例缩放人物，垂直增加可见场景范围；指针位置按相同缩放和垂直偏移逆算，不通过 CSS 拉扁人物来铺满战场。自动开火仅在尚未 firing 时调用 press，模拟层也独立保护同一次长按的冷却。原版普通 4 发/秒、奖励 12 发/秒、激光 4 次/秒、散弹 2 发/秒维持不变。

类型检查与 Vinext build 为构建入口。Sites 的包装 build 脚本在当前机器仍有 npm 路径异常，使用同一已安装 Vinext CLI 直接成功构建，未改依赖规避。开发服务保持 3010；旧 8080 服务不被替换。
